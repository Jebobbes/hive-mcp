# Work with Hive

Start with `read_product_knowledge`, when available, when checking capabilities, pricing or release freshness. Use the connection's available tools and returned permissions as the current source of truth. If a saved client scan omits that tool or `list_workspace_operations`, use only the tools the client actually exposes and ask the person to refresh tool discovery. Reconnect only when Hive reports expired or missing authorization, or the person chooses to grant a newly required permission; tool absence or schema drift alone calls for tool discovery refresh and never expands a grant. A new package does not update the hosted server, the saved tool scan or the existing OAuth grant. The installed package can outlive a tool scan or a saved OAuth grant; do not infer full control from its description.

For a first visit, help the person complete their requested task rather than listing features. Hive OAuth uses their signed-in Hive account and chosen workspace; it does not create an account from their AI client's email. New customers create a real Hive account and verify their email before authorizing a workspace. If they already signed into Hive, they may not see sign-in again. Never say that installing the plugin connected a social account or completed onboarding.

If `read_channels` returns no accounts, offer the workspace-specific connection link returned by Hive for the person to connect the network they requested. Preserve the returned link exactly so the browser uses the same workspace as this connection. They complete the provider sign-in and permission screen themselves, then return to this chat. Read the channels again and confirm the exact account before continuing. If they lack access rather than having an empty workspace, explain that distinction. Do not claim connection from a clicked link or ask for a social password. A permitted private post can be drafted before connection: use `create_draft` with `channelIds: []`, then confirm actual connected destinations before scheduling or publishing. Hive Bio, private ideas and campaigns can also be useful before any channel is connected. Offer one relevant next action, not a long setup checklist. For multiple-network publishing, confirm each destination, prepare a private draft, validate it, and follow the current confirmation policy before scheduling or publishing. For an automation, prepare and inspect its saved flow before offering activation. For Hive Bio, save and inspect the draft before offering public publication.

Hive's no-card trial includes one social account for 14 days. Use the returned workspace-specific deadline and help the person complete one useful task with it before offering expansion. Do not promise multiple connected accounts during the trial. Use current pricing and billing tools for an eligible paid plan when another account is needed. Payment details belong in Hive checkout. An expired trial or unavailable billing check does not require reconnecting OAuth, creating another Hive account or restarting the trial; follow the returned recovery result.

For actions targeting social accounts, read `read_channels` and use its account IDs. Clarify when multiple accounts match the user's request. For content work, use the named drafting, publishing, campaign and analytics tools. Media links must satisfy Hive's composer rules; import public media through `upload_media_from_url` when necessary.

For Asset Library work, read `read_media_library` to get accessible assets, folders, channel groups and library capabilities. A library role may differ from the person's workspace role. When visibility is per channel group, pass the selected `channelGroupId` when importing; do not choose an unrelated group or assume workspace-wide visibility. Library use and editing rights are distinct: adding an asset to a draft does not grant permission to change its saved accessibility text. Discover folder, snippet, asset-tag and library-setting controls through `list_workspace_operations`.

For Hive Bio, read `read_bio_page` and `describe_bio_blocks`. Prepare an edit with `prepare_bio_edit`, its requested operation and change fields, the known draft version when available, and one original request key. Preparation creates nothing. If it returns `consent_required`, use its protected `settingsUrl` so a workspace administrator can review the workspace-wide External AI choice; do not retry preparation or invent save arguments before that choice is made. Keep the returned `saveArguments` unchanged and call its `saveTool`: `create_bio_page` for an absent page, or `update_bio_document` for an existing draft. The complete document, generated block IDs and expected version belong to that one prepared attempt; do not regenerate them to retry a save. An address retained by an older Hive Bio page requires the returned native Hive handoff.

After uncertain Bio save delivery, call `read_bio_document_save_receipt` with the original `saveArguments`; for initial creation also include the returned `recoveryOriginalOperation` as `originalOperation`. Do not prepare or save again to recover a reply. Use the dedicated version-bound publish or unpublish tools for public visibility, retaining their exact saved version and original request key. A historical receipt establishes the original action, not the page's current public state; read the page again when current visibility is needed. Changing a live public address uses the returned Hive screen handoff.

For a Hive short link, use `prepare_bio_short_link` to resolve the destination, public address and defaults without creating anything. Keep its complete returned proposal unchanged, then call `create_bio_short_link` with that proposal and one original request key, following any returned human confirmation. After uncertain delivery, use `read_bio_short_link_creation_receipt` with the original proposal and key; never prepare a different address or repeat creation to recover a reply. Its historical receipt describes the original creation, even if the link was later edited, disabled or removed. External provider links use their returned native Hive setup flow.

For booking services and weekly hours, use `read_bio_genie_catalog` when available. It reads the original connected Genie's configuration without changing it or reserving a booking. Preserve masked service text. Configured hours are not proof of a live available slot or payment readiness. If it returns `consent_required`, follow its protected `settingsUrl` for a workspace owner or admin to review the External AI choice, then wait for that choice before reading again. Booking and configuration changes still require their available native Hive controls.

For Honeycomb, use the available flow document and node-catalog tools. Inspect the existing flow and its version before editing; preserve unrelated nodes and connections. Activation follows Hive's exact-action approval rules.

For Sequences, read the sequence before changing status and send its exact reviewed `expectedRevision`. If it changed, read and review it again; never substitute a newer revision into an existing approval. Publishing saves an immutable version for enrollment and does not itself enroll anyone or send a message. To enroll a contact, review `publishedDocument` from `read_sequence` and supply its exact `currentVersion` as `expectedVersion`. Enrollment requires automation activation permission and reply access to the contact’s account. If the publication changed, request a fresh review and approval; never silently switch versions or reuse an approval for a newer publication. A committed replay keeps its original enrollment, and consent, pause and existing-enrollment results must be reported as returned rather than described as a new send.

For analytics, `read_best_times` gives account suggestions and `read_post_performance` returns a bounded summary. Discover `read_best_time_heatmap` for objective, timezone, window and account selection, or `read_post_performance_dataset` for the complete native table. A posting schedule is not measured performance; missing snapshots are unknown, not zeros. Large tables may return a result reference; a native row-limit error requires a smaller date range.

For Reviews, discover `read_live_business_reviews` and follow its provider `nextPageToken` with `pageToken`; stored workflow summaries are not the complete Google review list. `delete_business_review_reply` removes only the business's own reply and follows the connection's exact-action approval policy. Before changing assignments or labels, read the review and pass the complete intended assignee, status, channel and label list, including null for deliberate clearing. `save_review_workflow` edits all those fields together. Discover review workflow and report operations for filters and CSV output; private workflow/report access requires the workspace's external-AI consent. Report coverage does not claim full provider history.

When a named tool does not cover the requested control and `list_workspace_operations` is available, call it with a relevant word. Read the exact operation descriptor, then pass only its listed path, query and body fields to the indicated read, write or administration tool. If discovery is unavailable, follow the tool-refresh guidance above without inventing a control. Never invent operation IDs, methods, hosts or workspace selectors. A static API key cannot impersonate the connected person's OAuth session.

If an operation returns `resultId`, use its `retrievalTool` to read the existing result; never repeat the original action to obtain more data. `read_workspace_result` supports JSON pointers, successive `nextOffset` pages and `download: true` for the complete sanitized JSON. Concatenate text pages before parsing and retrieve them before the stated expiry. The same connection and current permissions are required. A response with `nativeRequestCompleted` and `resultDelivery: unavailable` means result delivery failed after the native request returned; honor `doNotRepeat`, inspect the affected Hive record and do not claim the business action succeeded from that response alone.

For files, discover the upload reservation and completion operations. A reservation does not mean bytes were uploaded: transfer the file to its returned single-object signed URL using only the returned upload headers, never Hive's OAuth credentials. Large media may require signed parts and completion using their ETags. Hive Bio media must pass its native completion/readiness checks before attachment; digital products and course lessons use the private-file reservation. If the host cannot transfer file bytes, explain that host limitation and use Hive's uploader without claiming success.

Honor the connection's granted scopes. If a scope is missing, explain that the person must reconnect and grant it; do not expand it yourself. Administration always requires a separate approval inside Hive. When Hive returns a confirmation link, present it and wait for the person, then retry the exact approved arguments. Do not approve your own actions or report success before Hive returns success.

Private text requires a workspace owner or admin to enable both external-AI access and private-text sharing under Settings > Security > Data policy. Use masked and redacted reads by default. When the person explicitly requests original Inbox text, discover `reveal_inbox_conversation`, `reveal_inbox_private_notes`, `reveal_inbox_team_chat` or `reveal_inbox_contact_profile` as appropriate. Use only the returned operation under its current scope, native reveal permission, write confirmation and mandatory per-use audit; an ordinary redacted read never authorizes revealing originals. Preserve masked values when editing until an authorized reveal supplies the actual value. Permitted native private exports can also contain originals; discover only the returned export operation and follow its own scope, access, consent, confirmation and audit requirements. An export does not grant extra access or authorize an unrelated reveal. Provider authorization, card entry, password changes, security challenges and other returned browser steps are completed by the person in the indicated Hive screen.

For pricing or product claims, use Hive's current product information tools or <https://hivepublish.com/ai-info> instead of fixed package copy.

Before changing an existing simple automation, use `read_automation_flow` and keep its exact `draftVersionId` and positive `revision`. Send them as `expectedDraftVersionId` and `expectedRevision` to `update_simple_automation`. If Hive reports a conflict, inspect the newer draft and ask the person about the intended changes. Never replace the original expectations merely to force the older edit through. Account discovery and selection cover only accounts the connected person can access.

For an owner or admin changing the private booking-notification recipient, read `read_bio_page` for the `pageId` and discover `read_bio_notification_email` for the setting version and masked destination. Version zero uses the page creator's email, rather than disabling delivery. Use `set_bio_notification_email` with the full chosen lowercase email, original `expectedVersion` and original request key. The person must approve the exact destination inside Hive, even when their connection does not generally ask again there. Saving sends nothing, does not enable notifications and does not reroute already addressed queued mail. Recover an interrupted reply with `read_bio_notification_email_receipt` using the unchanged original arguments and key. Its receipt is historical, not a statement of the current destination. Product-support mailbox verification stays a separate human step.


For CRM actions, discover the Salesforce and HubSpot operations. Review the selected Inbox contact profile and the current Salesforce mapping before requesting a sync. Approval names the external destination and sends the contact profile as saved when the action runs; it is not a frozen historical profile snapshot. Supply an explicit stable `requestKey` for the same Salesforce attempt. Report pending/duplicate/provider-refused outcomes accurately. If `providerAccepted` is true with `syncRecorded` or `auditRecorded` false, retain the returned Salesforce record id and follow `doNotRepeat`; never resend merely to repair Hive bookkeeping. HubSpot matches by email; its event key is not proof of exactly-once provider execution. Configuration reads mask private values, so use `preserveStaticValues:true` when changing Salesforce mappings without changing saved fixed values, or supply the intended complete `staticValues` explicitly. Initial provider authorization still uses Hive’s protected connection screen.

For an existing near-real-time Listening source, read `read_listening_realtime`, then use `update_listening_realtime_source` to edit its query, provider label, timing, all four thresholds, or enabled state. Copy the exact source `updated_at` into `expectedUpdatedAt`; supply the full configuration for approval. A stale source must be read and approved again. Its provider credential is retained automatically; never request or send that credential in the tool arguments, and never use provider ingest to invent listening evidence.

Listening report tools return Hive's complete native coverage disclosure. Keep `read_listening_trends`'s native and licensed groups separate. For trends, comparison, benchmarks and forecasts, use the returned source, window, freshness and completeness; do not describe bounded or missing evidence as complete. `evidenceSource` describes saved-capture provenance without replacing the report's native `source`. An unavailable forecast is not a forecast of zero activity.

For connected accounts, use `read_connected_account_catalog` to identify the exact visible account and native readiness. Disconnection is destructive: explain that associated Hive data and planned content with no remaining destination can be removed. Use approved `disconnect_social_account`, or `disconnect_telegram_account` for Telegram; Instagram requires the existing removal-impact review and `remove_instagram_channel`. These require owner/admin account-management access. After a successful local removal, report provider cleanup separately from `ok`; do not repeat deletion to repair an incomplete webhook cleanup. Connecting/reconnecting still requires the provider's protected sign-in or credential setup.

Use `read_workspace_activity` for the native activity feed and `download_workspace_audit` for an authorized private audit CSV (`format:csv`). Both use inclusive from/to dates and native prefix/limit filters. The feed is capped at 500 rows and export at 10,000; narrow the date range when needed. Private-text consent applies, and downloads additionally require `write:settings`, the approved write tool, workspace administration permission and successful native export auditing. Creating the recorded export is an action, even though its native endpoint uses GET. Do not infer an empty history from a failed read or release a file after an audit failure.


For the connected person’s own Hive Assistant chats, use `read_my_assistant_chats` and `read_my_assistant_messages`; reads are bounded at 100 chats or 200 messages and require private-text consent. Create, update (including archive/restore) or delete with the corresponding `*_my_assistant_chat` write controls. `send_my_assistant_message` uses the chat’s current saved provider/model, can consume credits and returns the completed answer with evidence and pending proposals. Proposals still need their own native confirmation where required; never treat them as completed actions or attempt to approve them for the person. The nested Assistant retains your granted scopes. After uncertain delivery or a usage-accounting warning, inspect saved messages and honor `doNotRepeat` instead of making another paid request to recover its answer.
